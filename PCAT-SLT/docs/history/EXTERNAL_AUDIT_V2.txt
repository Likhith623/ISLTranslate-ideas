### Category A: Mathematical & Theoretical Limitations

#### 1. The Single Common-Clock Restriction (Theorem 3 Dilemma)
- **The Issue**: PCAT’s mathematical invariance applies **only** when all articulators share the *exact same* reparameterization $\phi(t)$ ($z \mapsto z \circ \phi$).
- **Why it breaks in reality**: Human sign language is **asynchronous across articulators**. A signer’s dominant hand may accelerate during a rapid fingerspelling burst while the base hand stays stationary, and the mouth forms a slow, sustained vowel. 
- PCAT explicitly proves in Theorem 3 that quotienting out independent articulator clocks destroys cross-articulator order. As a result, PCAT cannot be fully invariant to independent articulator speed variations without corrupting the cross-articulator signed area ($H_k$).

#### 2. Static First-Frame Coordinate Normalization (`geometry.py`)
In `BodyFrame` (`geometry.py`, lines 38–56):
```python
index = self.reference_indices(pose, confidence, lengths)  # Finds frame 0
centered = (pose - origin[:, None, None, :]) / width[:, None, None, :]
return torch.einsum("btjc,bcd->btjd", centered, basis)
```
- **The Issue**: The anatomical coordinate basis $B = [e_1, e_2, e_3]$ and torso origin are extracted **exclusively from the first reliable frame** and kept frozen for the entire clip.
- **Why it breaks**: If the signer shifts their weight, leans forward, steps slightly, or rotates their torso over a 10-second sentence, coordinates drift relative to that initial anchor.

#### 3. Quadratic Dimension Explosion in Signed Area ($H_k$)
In `operators.py` (lines 76–77):
$$H_k = \frac{1}{2}\sum_{j<i} (v_j v_i^\top - v_i v_j^\top) \in \mathbb{R}^{N \times N}$$
- If you have $A=4$ articulators and feature rank $r=32$, $N = A \times r = 128$.
- The signature area $H_k$ has $128 \times 128 = 16,384$ entries per progress cell.
- If you increase to $A=6$ articulators (DH, BH, Face, Mouth, Left Arm, Right Arm) and rank $r=64$, $N=384$, meaning $H_k$ has **147,456 elements per cell**. This causes memory and computation bottlenecks.

#### 4. The Monocular Depth Ambiguity Assumption
- PCAT’s Theorem 1 (proper-similarity invariance) assumes that input coordinates are **ground-truth 3D Euclidean coordinates** ($\mathbb{R}^3$).
- In practice, landmarks come from monocular 2D video via MediaPipe or OpenPose. Monocular depth ($z$) is notoriously noisy, estimated up to an arbitrary projective scale, and flips under hand-hand occlusions. PCAT’s 3D geometric guarantees cannot fix 2D projection ambiguities.

### Category B: Linguistic & Translation Limitations

#### 1. The "No-Pixels" Blindness (Total Absence of Mouthings & Gaze)
- **The Issue**: PCAT takes **3D landmarks only**. It has zero RGB pixel input.
- **Why it breaks translation**: In sign languages (ISL, DGS, ASL), over 30% of lexical signs have identical hand trajectories and are disambiguated **exclusively by mouthings** (silent words mouthed by the lips). Grammatical questions vs. statements are signaled by eye gaze and eyebrow height. Landmarks cannot capture lip texture, teeth/tongue visibility, or gaze direction.

#### 2. The Scratch UTF-8 Byte Decoder Trap (`model.py` & `tokenizer.py`)
- **The Issue**: PCAT uses a 4-layer Transformer decoder trained from scratch over raw UTF-8 bytes (vocabulary size = 256 + 3 special tokens).
- **Why it breaks**: Sign language translation datasets are small (e.g., PHOENIX-2014T has ~7,000 sentences; ISLTranslate has ~3,000). A tiny decoder trained from scratch on raw bytes without pretrained language priors requires massive data to learn English grammar, leading to syntax collapse or repetitive hallucinations on natural language.

#### 3. Fixed $K$-Cell Temporal Quantization
- In `config.py`, progress cells are fixed ($K=16$ or $K=32$).
- A 2-second short sign ("YES") gets allocated 16 cells, and a 12-second complex multi-clause sentence also gets allocated 16 cells. For long sentences, 16 cells over-compresses the sequence, blending distinct signs into a single cell.

### Category C: Engineering & Runtime Bottlenecks

#### 1. High Latency from Exact Matrix Solves (`torch.linalg.solve`)
In `cayley()` (`operators.py`, line 25):
```python
return torch.linalg.solve(eye - skew, eye + skew)
```
- `torch.linalg.solve` performs an exact $LU$ decomposition. On GPUs, launching hundreds of small batched linear solves for every batch and progress cell introduces high kernel-launch overhead compared to standard matrix multiplications.

#### 2. Apple Silicon / MPS Incompatibility
- `torch.linalg.solve` for batched skew-symmetric systems frequently fails or falls back to CPU on PyTorch MPS devices.

### Upgrade 1: Visually Grounded Articulators (Fixes the No-Pixels Blindness)
**What to change**: Augment the affine articulator embedding in `model.py` so that each articulator channel combines coordinates with local visual appearance.

**Implementation**:
```python
# In src/pcat_slt/model.py
class VisuallyGroundedArticulator(nn.Module):
    def __init__(self, landmark_dim: int, visual_dim: int, rank: int):
        super().__init__()
        self.pose_proj = nn.Linear(landmark_dim, rank)
        self.vis_proj = nn.Linear(visual_dim, rank)
        self.fusion = nn.Linear(rank * 2, rank)
        self.norm = nn.LayerNorm(rank)

    def forward(self, coords: torch.Tensor, visual_crops: torch.Tensor) -> torch.Tensor:
        h_pose = self.pose_proj(coords)
        h_vis = self.vis_proj(visual_crops)
        return self.norm(self.fusion(torch.cat([h_pose, h_vis], dim=-1)))
```
*Result*: Mouth and eye regions now feed lip and gaze pixel features directly into the PCAT progress engine.

### Upgrade 2: Replace Scratch Byte Decoder with a Pretrained LLM (FLAN-T5)
**What to change**: Replace the 4-layer scratch byte decoder in `model.py` with cross-attention into **FLAN-T5-base** or **mBART-50**.

**Implementation**:
```python
from transformers import AutoModelForSeq2SeqLM

class PretrainedTextDecoderAdapter(nn.Module):
    def __init__(self, pcat_width: int, pretrained_model: str = "google/flan-t5-base"):
        super().__init__()
        self.t5 = AutoModelForSeq2SeqLM.from_pretrained(pretrained_model)
        self.proj = nn.Linear(pcat_width, self.t5.config.d_model)

    def forward(self, pcat_memory: torch.Tensor, target_ids: torch.Tensor):
        # Project PCAT tokens to T5 dimension
        encoder_hidden_states = self.proj(pcat_memory)
        return self.t5(
            encoder_outputs=(encoder_hidden_states,),
            labels=target_ids,
            return_dict=True
        )
```
*Result*: Translation fluency immediately jumps from broken byte tokens to grammatically correct sentences.

### Upgrade 3: Causal Windowed Coordinate Normalization (Fixes First-Frame Drift)
**What to change**: Upgrade `BodyFrame` in `geometry.py` from a static first-frame freeze to a causally smoothed exponential moving average (EMA) reference frame.

**Implementation**:
```python
# In src/pcat_slt/geometry.py
def causal_smoothed_body_frame(pose: torch.Tensor, alpha: float = 0.95):
    """
    Computes body frame with causal EMA smoothing of torso origin and shoulder width.
    Eliminates drift over long signing clips.
    """
    B, T, J, C = pose.shape
    origins, widths = [], []
    curr_origin = (pose[:, 0, 11] + pose[:, 0, 12]) / 2.0  # Shoulders
    curr_width = torch.linalg.norm(pose[:, 0, 12] - pose[:, 0, 11], dim=-1, keepdim=True)

    for t in range(T):
        inst_origin = (pose[:, t, 11] + pose[:, t, 12]) / 2.0
        inst_width = torch.linalg.norm(pose[:, t, 12] - pose[:, t, 11], dim=-1, keepdim=True)
        curr_origin = alpha * curr_origin + (1 - alpha) * inst_origin
        curr_width = alpha * curr_width + (1 - alpha) * inst_width
        origins.append(curr_origin)
        widths.append(curr_width)

    origins = torch.stack(origins, dim=1).unsqueeze(2)
    widths = torch.stack(widths, dim=1).unsqueeze(2)
    return (pose - origins) / widths.clamp_min(1e-6)
```

### Upgrade 4: Fast Padé / Neumann Series for Cayley Solves (Fixes GPU & MPS Latency)
**What to change**: Replace `torch.linalg.solve(eye - skew, eye + skew)` with a 2nd-order or 3rd-order Padé approximation when running on GPU or MPS:
$$(I - A)^{-1}(I + A) \approx (I + A + A^2 + A^3)(I + A)$$
Since $\|A\|_F < 1$ by construction (scaled by $\tanh(g)/(1 + \|H\|_F)$), the Neumann series converges rapidly, replacing slow linear solves with fast parallel matrix multiplications (`torch.bmm`).
